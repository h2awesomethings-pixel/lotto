# 로또 통계 실험실

역대 로또 6/45 데이터를 기반으로 번호 Feature와 조합 Feature를 분리해 계산하고, 여러 전략이 무작위 기준선보다 나은지 Walk-forward 방식으로 검증하는 정적 웹 애플리케이션입니다.

당첨번호를 예언하거나 당첨확률 증가를 보장하는 서비스가 아닙니다. Hot/Cold와 조합 패턴은 검증 대상 Feature일 뿐, 다음 추첨 확률을 바꾸지 않습니다.

## 주요 기능

- 1~45 번호별 전체 및 최근 20·50·100회 출현 빈도
- 현재 출현 간격, 평균 간격, 장기 편차 및 pair lift
- Momentum, Cold, Neutral, Hybrid, Random 전략
- 후보 15개의 5,005개 조합 전수 평가 및 가중 무작위 생성
- 홀짝, 합계, 구간, 연속수, 전 회차 중복, 끝수, 거리, pair 조합 점수
- 두 게임 사이 동일 번호를 최대 3개로 제한하는 다양성 선택
- 미래 데이터 유입을 차단한 Walk-forward 백테스트
- Random 후보 선택 1,000회 분포와 전략별 p-value 비교
- Seed 기반 결과 재현 및 JSON 결과 저장
- DB와 서버 없이 GitHub Pages에서 실행

## 로컬 실행

Node.js 22 이상을 사용합니다.

```bash
npm install
npm run dev
```

화면에 표시된 로컬 주소로 접속합니다.

## 테스트와 빌드

```bash
npm test
npm run build
npm run preview
```

`dist` 디렉터리가 GitHub Pages에 배포되는 최종 결과입니다. 저장소 이름이 `lotto`이므로 Vite의 기본 경로는 `/lotto/`로 설정되어 있습니다.

## 당첨 데이터

역대 데이터는 `public/data/lotto-draws.json`에 다음 형식으로 저장됩니다.

```json
{
  "drawNo": 1241,
  "drawDate": "2026-09-12",
  "numbers": [7, 13, 16, 23, 24, 43],
  "bonus": 9
}
```

공식 동행복권 결과 화면이 사용하는 조회 요청을 통해 전체 데이터 또는 누락된 최신 회차를 가져옵니다.

```bash
npm run data:update
```

갱신 전 다음 조건을 모두 검증합니다.

- 1회부터 최신 회차까지 빠짐없이 연속적인지
- 당첨번호가 서로 다른 6개인지
- 모든 번호가 1~45 범위인지
- 보너스 번호가 당첨번호와 겹치지 않는지
- 날짜가 `YYYY-MM-DD` 형식인지

검증 실패 시 기존 데이터 파일은 수정하지 않습니다.

## 자동 갱신과 GitHub Pages

`.github/workflows/pages.yml`은 다음 상황에 실행됩니다.

- `main` 브랜치에 코드가 반영될 때
- GitHub Actions 화면에서 수동 실행할 때
- 매주 일요일 00:30, 02:30, 04:30 한국 시간

예약 실행은 새 회차가 확인된 경우에만 데이터 파일을 자동 커밋합니다. 이어서 테스트와 빌드를 통과한 결과만 GitHub Pages에 배포합니다.

저장소의 **Settings → Pages → Build and deployment → Source**를 `GitHub Actions`로 한 번 설정해야 합니다.

## Feature와 Score

가중치와 조합 제한은 `public/config/strategy-config.json`에서 변경할 수 있습니다. 후보 수, 게임 수, Momentum·간격·pair 비중, 조합별 비중, 합계 평균과 표준편차, 게임 간 최대 중복 수가 한 파일에 모여 있습니다.

번호 Feature는 기준 회차까지의 데이터만 사용합니다. 최근 빈도는 45개 번호 안에서 z-score로 정규화하고, 평균 간격이 없는 번호에는 이론적 평균 간격 `45 / 6`을 사용합니다. Pair lift에는 표본이 적을 때 값이 과도하게 커지는 것을 줄이기 위해 1회의 smoothing을 적용합니다.

번호 전략은 서로 독립적으로 계산합니다.

- `MOMENTUM`: 최근 20·50·100회 출현 강도를 0.5, 0.3, 0.2 비율로 평가합니다.
- `COLD`: 평균 출현 간격 대비 현재 간격을 주로 평가합니다.
- `NEUTRAL`: 최근 및 장기 빈도가 평균에서 크게 벗어나지 않은 번호를 선호합니다.
- `HYBRID`: Momentum, 간격, 장기 균형, 최근 균형, pair를 낮은 무작위 변동과 함께 조합합니다.
- `RANDOM`: 같은 조건으로 비교하기 위한 Seed 기반 무작위 기준선입니다.

조합 점수는 번호 평균 점수와 별개로 계산합니다. 홀짝 비율과 합계 138 부근을 선호하지만 극단적인 조합도 하드 필터로 제거하지 않습니다. 최종 선택에서만 게임 사이 중복 번호 수를 제한합니다.

## 백테스트 해석

N회차를 평가할 때 반드시 1회부터 N-1회까지의 데이터만 사용합니다.

- 후보 평균 적중: 후보 15개에 실제 당첨번호가 평균 몇 개 포함됐는지 나타냅니다.
- 최고 게임 평균: 추천 게임 중 가장 많이 맞은 게임의 평균 일치 개수입니다.
- 3+/4+ 비율: 추천 게임 중 하나라도 3개 또는 4개 이상 맞은 회차 비율입니다.
- Random 기대값: 후보 15개라면 이론적 평균은 `6 × 15 / 45 = 2`개입니다.
- Random 95% 범위: 동일 회차 구간을 1,000번 반복한 무작위 후보 평균의 중앙 95% 범위입니다.
- p-value: 무작위 후보가 해당 전략의 평균 적중 이상을 기록한 비율입니다. 일반적으로 값이 작을수록 우연만으로 설명하기 어렵지만, 이것만으로 예측력이 증명되지는 않습니다.

한 기간의 미세한 우위만으로 전략이 우수하다고 판단하면 안 됩니다. 여러 비중을 시험할 때는 튜닝 기간과 최종 평가 기간을 시간순으로 분리해야 합니다.

## 운영상 주의사항

동행복권이 자동 수집용 공개 API의 안정성을 보장하는 것은 아닙니다. 공식 사이트의 주소나 응답 형식이 변경되면 예약 작업이 실패할 수 있으며, 이 경우 기존 검증 데이터와 Git 이력은 그대로 유지됩니다. GitHub Actions 실패 알림을 확인한 후 수집 스크립트를 조정해야 합니다.
